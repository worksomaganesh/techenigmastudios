What Actually Happens When You Press Send?

Evidence-backed technical research dossier for TECHENIGMASTUDIOS Episode 001 (60-second beginner explainer): tracing a text prompt through a generic modern autoregressive LLM architecture. Sources verified and accessed 22 November 2026.

Core technical thesis: An AI chat assistant does not "read" a message and look up a stored answer in a database. Instead, an application layer packages your prompt and conversation context into a formatted token sequence, converts subword pieces into numerical vectors with positional information, runs them through stacked self-attention and feed-forward layers to score every vocabulary token, and predicts one next token at a time in an autoregressive loop until a stop condition is met.

A. Research Brief: Seven Stages Inside an Autoregressive LLM

Each stage below separates established mechanics shared by typical modern autoregressive Transformer LLMs from implementation-dependent choices that vary across model providers, serving stacks, and architectures. No narration script or storyboard is included at this stage.

1. User Input and Request Handling

Scope: Generic client-to-backend flow, API request payload, optional streaming

In a generic LLM application architecture, pressing Send instructs the client to package the prompt into a structured network request (commonly an HTTPS POST payload containing the model identifier, message inputs, and generation parameters) and send it to a backend inference service (OpenAI Conversation State; Claude Messages API). Rather than waiting for the entire reply to finish, many LLM APIs support incremental streaming—commonly delivered over HTTP using Server-Sent Events (SSE)—so text chunks can appear as they are generated, while transport protocols and implementations vary across providers and clients (OpenAI Streaming Responses; Claude Streaming Docs).

Implementation-dependent & scope note: This request path is a generic reference architecture, not a verified internal system diagram of proprietary products such as ChatGPT or Gemini. Authentication, rate limiting, load balancing, safety classifiers, tool-routing middleware, and transport choice (non-streaming JSON HTTP, SSE, WebSockets, or custom framing) are product and infrastructure choices rather than properties of the neural network itself.

2. Conversation Context and Instruction Assembly

Scope: Model statelessness vs. application state, roles, chat templates, context window

It is essential to separate the underlying model's lack of persistent conversational memory from application-managed conversation state. A causal language model processes only the tokens present in the current forward pass; to maintain multi-turn continuity, applications may either resend relevant prior conversation history (within the model's context window) or reference server-managed thread or conversation IDs—such as OpenAI's Responses/Conversations APIs or Anthropic's beta message threads—so the backend reconstructs the active context (OpenAI Conversation State; Claude Messages API). Because a causal LLM continues a single sequence of tokens, a chat template flattens the structured list of system, user, and assistant messages into one formatted string with special role-delimiter tokens—and appends a generation prompt signaling that it is now the assistant's turn to reply (Hugging Face Chat Templates).

Implementation-dependent: Not every provider or application resends the entire raw conversation on every request; systems may truncate, summarize, compact, or store history server-side. Exact control tokens also differ sharply across models even when fine-tuned from the same base (for example, Mistral-7B-Instruct uses [INST]/[/INST] while Zephyr-7B uses <|user|> and <|assistant|>).

3. Tokenization and Token IDs

Scope: Subword segmentation, integer ID lookup, vocabulary mapping

Neural networks operate on numbers, not raw text. A tokenizer breaks the assembled string into tokens and maps each token to an integer ID in the model's fixed vocabulary (Hugging Face Tokenization Algorithms). Crucially, tokens are not necessarily whole words: modern LLMs use subword algorithms—most commonly Byte-Pair Encoding (BPE) (Sennrich et al., 2016), Byte-level BPE (Radford et al., 2019), Unigram, or SentencePiece (Kudo & Richardson, 2018). Common words often stay whole, while rare or compound words split into pieces (for example, annoyingly may split into ["annoying", "ly"] or ["annoy", "ing", "ly"]), and spaces, punctuation, or UTF-8 bytes can be part of tokens (Hugging Face Tokenization Algorithms; OpenAI tiktoken).

Implementation-dependent: Vocabulary sizes, merge tables, special tokens, and integer ID assignments are model-specific—never assume a universal token ID or fixed word-to-token ratio across models or languages.

4. Token Embeddings and Positional Information

Scope: Embedding matrix lookup, continuous vectors, architectural position mechanisms

Each integer token ID indexes a learned vector of floating-point numbers—its token embedding—from an embedding matrix (Vaswani et al., 2017). Because self-attention processes prompt tokens without built-in recurrence or convolution, positional information must be represented so the model can account for token order (Vaswani et al., 2017). Crucially, not every model adds a separate positional embedding vector to the token embeddings: positional information is represented through different architectural mechanisms, including additive sinusoidal or learned positional encodings (Vaswani et al., 2017), Rotary Position Embedding (RoPE), which rotates query and key vectors inside attention (Su et al., 2021/2023), and attention biases such as ALiBi, which apply distance-proportional penalties directly to query-key attention scores (Press et al., 2021).

Implementation-dependent: Embedding vector dimensions, weight tying between input embeddings and the output projection, and the specific positional mechanism (additive encodings, RoPE and its long-context scaling variants, ALiBi, or other schemes) differ across architectures.

5. Transformer Layers and Self-Attention

Scope: Causal multi-head self-attention, feed-forward blocks, residual stream

The sequence of token vectors passes through a stack of Transformer layers. Inside each layer, two core sub-blocks refine every token's numerical representation using residual connections and normalization (Vaswani et al., 2017). First, causal multi-head self-attention projects each token vector into Query (Q), Key (K), and Value (V) vectors, computes scaled dot-product attention softmax(QKT / √dk)V, and applies a causal mask (setting illegal future positions to −∞ before softmax) so each token can only attend to itself and earlier positions (Vaswani et al., 2017; Hugging Face Caching Docs). Running multiple heads in parallel lets the layer combine information across different representation subspaces simultaneously. Second, a position-wise feed-forward network (FFN) transforms each position's vector independently (Vaswani et al., 2017).

Implementation-dependent: Layer count, head count, normalization type (LayerNorm vs. RMSNorm; Pre-LN vs. Post-LN), FFN activations, attention head sharing (MHA vs. Grouped-Query Attention in Ainslie et al., 2023 and Llama 3, 2024), and dense vs. Sparse Mixture-of-Experts FFN routing (e.g., 2 of 8 experts active per token in Mixtral 8x7B, 2024) all vary by model.

6. Logits, Probability Distributions, and Decoding Strategies

Scope: Unembedding projection, logits vs. probabilities, greedy vs. sampling decoding

After the final Transformer layer, a linear output projection maps the last token's hidden vector into a vector of raw, unnormalized scores—one score for every token in the vocabulary. These raw scores are called logits (Vaswani et al., 2017; Hugging Face Generation Utilities). Logits are not probabilities: logits can be any positive or negative real number and do not sum to 1. Applying the softmax function converts logits into a probability distribution where every token lies between 0 and 1 and all probabilities sum to 1 (Vaswani et al., 2017).

A decoding strategy then selects the next token from that distribution (Hugging Face Generation Strategies). Depending on the model, task, and generation configuration, decoding may use deterministic greedy selection (picking the single highest-probability token), beam search (tracking multiple candidate sequences), or probabilistic sampling. In open-ended generation, pure maximization methods can produce repetitive text, which motivated truncated sampling strategies (Holtzman et al., 2019/2020). When sampling is enabled, optional controls shape the distribution: temperature scales logits before softmax, top-k retains only the k highest-scoring tokens, and top-p (nucleus sampling) retains the smallest set of top tokens whose cumulative probability reaches p (Holtzman et al., 2019/2020; Hugging Face Text Generation API).

60-second editorial priority & variance: For the 60-second beginner episode, prioritize the core three-step sequence logits → probability distribution → next-token selection, treating temperature, top-k, and top-p as optional deeper details. Default decoding configurations, warper ordering, min-p filtering, repetition penalties, and structured-output constraints vary by provider and runtime.

7. Autoregressive Generation Loop and Final Text Decoding

Scope: Prefill vs. decode, per-layer KV cache, stopping criteria, detokenization

Once one next token ID is chosen, the model appends that token to the sequence and repeats the forward pass to predict the token after it—this one-token-at-a-time feedback loop is why modern LLMs are called autoregressive (Vaswani et al., 2017; Hugging Face Caching Docs). Because causal masking ensures that earlier tokens' attention states do not change when new tokens arrive, inference engines separate generation into a parallel prefill pass over the prompt and a sequential decode loop. In each Transformer layer, a KV cache stores the previously computed Key (K) and Value (V) tensors: on each decode step, the model computes only the new token's query, key, and value states, appends the new K/V states to that layer's cache, and attends over the combined past and current K/V tensors—reducing per-step attention compute from quadratic to linear in sequence length (Hugging Face Caching Docs; Pope et al., 2022).

The loop stops when the model emits a special End-of-Sequence (EOS) token, matches a configured stop sequence, or reaches the maximum token limit (Hugging Face Generation Strategies; OpenAI Conversation State). As token IDs are produced, the tokenizer's decoder maps them back into readable characters/bytes (buffering multi-byte UTF-8 sequences when needed) and returns or streams the resulting text to the user's interface (OpenAI tiktoken; OpenAI Streaming Responses).

Implementation-dependent: Production serving stacks may layer on speculative decoding, continuous batching, paged KV memory management, prefix caching, or multi-token prediction heads—optimizations that accelerate execution without changing the conceptual autoregressive loop.

D. Accuracy and Risk Report

Guardrails for scripting Episode 001 so the 60-second narrative stays clear for beginners without introducing technical myths or overstating provider-specific details.

Common Misconceptions to Avoid

  • "The AI searches its memory or a database for the answer." Autoregressive LLMs generate replies token-by-token from learned parameter weights conditioned on the current context window; they do not retrieve stored paragraphs unless an external search/RAG tool is invoked.
  • "One token equals one word." Subword tokenizers split rare words, punctuation, code, and non-English scripts into multiple tokens, while spaces are often attached to tokens.
  • "The model remembers our past chats inside its weights—or every app resends the whole chat raw." The neural network has no persistent conversational memory across requests, while applications manage state either by resending relevant history (often truncated or compacted) or by referencing server-side thread/conversation IDs.
  • "Attention arcs show what the AI is 'thinking' or 'understanding.'" Attention weights are mathematical weighting coefficients over earlier positions, not a faithful human-readable explanation of model reasoning.
  • "Logits are probabilities." Logits are unbounded raw scores output by the final linear head; only after softmax normalization do they become probabilities summing to 1.
  • "Every model adds a separate positional embedding vector." While the original Transformer added positional encodings, modern architectures may instead apply rotary transformations (RoPE) or attention biases (ALiBi).

Claims Simplified for a 60-Second Explanation

  • Decoding controls: Prioritizing logits → probability distribution → next-token selection keeps the 60-second arc crisp; temperature, top-k, top-p, and beam search can be omitted or flagged as optional deeper details.
  • Transformer internals: Referring to "self-attention layers and feed-forward blocks" omits mathematical details of layer normalization (RMSNorm/LayerNorm), residual stream addition, SwiGLU/GELU activations, and multi-head concatenation.
  • Positional representation: Explaining that "the model tracks each token's position in sequence" simplifies the mechanical difference between additive encodings, RoPE rotations, and ALiBi score biases.
  • KV caching & prefill/decode: Summarizing per-layer K/V caching as "reusing each layer's earlier key-value calculations" simplifies tensor memory layout, paged attention, and memory-bandwidth bottlenecks.
  • Generic request flow: Showing a clean client-to-server request omits multi-step agentic tool calls, safety classifiers, and hidden reasoning traces used by some assistants.

Details That Vary Across Providers & Architectures

  • Request transport & state management: Non-streaming JSON HTTP vs. SSE vs. WebSockets; stateless history replay vs. server-managed conversation/thread IDs and compaction rules.
  • Tokenizer & vocabulary: Byte-level BPE (e.g., tiktoken) vs. SentencePiece (Unigram/BPE) vs. WordPiece; vocabulary sizes range from tens of thousands to over 200,000 tokens.
  • Model topology: Dense decoder-only Transformers (e.g., Llama 3) vs. Sparse Mixture-of-Experts (e.g., Mixtral 8x7B activating 2 of 8 experts per token) vs. hybrid state-space/attention architectures.
  • Attention & position variants: Standard Multi-Head Attention (MHA) vs. Multi-Query (MQA) vs. Grouped-Query Attention (GQA) vs. Multi-Head Latent Attention (MLA); additive positional encodings vs. RoPE vs. ALiBi.
  • Decoding & serving configurations: Greedy selection vs. sampling defaults, temperature/top-k/top-p settings, prompt/prefix caching, continuous batching, and speculative decoding.

Claims Excluded Due to Insufficient Evidence

  • Internal pipelines of closed consumer apps: Do not present the generic 7-stage request path as a verified internal architecture diagram of ChatGPT, Gemini, or Claude.
  • Exact internal architecture of closed proprietary models: Do not claim specific layer counts, parameter counts, embedding dimensions, positional schemes, or MoE expert counts for closed models whose architectures are not publicly documented.
  • Universal latency or token-speed numbers: Do not state a single universal millisecond timing for "pressing Send to first word," as latency depends heavily on prompt length, batching, hardware, and network distance.
  • Claims about human-like "understanding" or "reasoning": Do not assert that internal attention weights prove comprehension or reveal human-style reasoning steps.
